# AqylRoute AI

Межведомственный маршрут семьи ребёнка с расстройством аутистического спектра:
адаптивное AI-интервью → Case Plan → контроль сроков → эскалация просрочки.

Прототип для Карагандинского медицинского университета.

## Запуск

```bash
./start.sh
```

Откроется `http://localhost:3000`. Скрипт сам создаст окружение и поставит зависимости.

### Учётные записи

| Логин | Пароль | Роль | Что показывает |
|---|---|---|---|
| `parent` | `parent123` | Родитель | Кейс «Раннее начало», план ещё не проверен куратором |
| `parent2` | `parent123` | Родитель | Кейс «Застрявший маршрут»: просрочка и блокер |
| `curator` | `curator123` | Куратор | Все кейсы, сводка, подтверждение планов |

### Своя учётная запись

На странице входа есть вкладка «Регистрация». Родитель регистрируется свободно,
указав имя, логин, пароль и регион.

Роль **куратора выдаётся по коду**, а не свободной регистрацией: куратор видит
кейсы всех семей, поэтому открытая выдача этой роли означала бы доступ
посторонних к чувствительным данным. Код задаётся в `.env`:

```
CURATOR_INVITE_CODE=KMU-2026
```

### Ключ OpenAI

Работает и без ключа — в демонстрационном режиме планировщик детерминированный,
по тому же справочнику услуг. Чтобы включить настоящую модель:

```bash
cp .env.example .env          # затем вписать ключ
```

Индикатор режима виден внизу страницы входа.

## Архитектура

```
Родитель → AI-интервью (12 вопросов ТЗ, адаптивный порядок)
             ↓
         CaseState — структурированное состояние семьи
             ↓
      SERVICE CATALOG — 20 услуг, 5 этапов, 3 региона
             ↓
       AI Case Plan (structured outputs)
             ↓
   ┌─────────┴─────────┐
   ↓                   ↓
Родитель видит      КУРАТОР правит сроки и шаги,
план сразу          ведёт статусы, отмечает проверенным
   └─────────┬─────────┘
             ↓  правки видны родителю немедленно
   Статусы → DEADLINE ENGINE → OVERDUE → ЭСКАЛАЦИЯ
```

### Как исключены выдуманные действия

Главное требование ТЗ — «AI не создаёт действия самостоятельно» — выполняется
не просьбой в промпте, а типом. Перед вызовом модели список допустимых
`service_id` подставляется в JSON Schema как `Literal`, суженный до услуг,
доступных этому региону и возрасту:

```python
ids = tuple(s["id"] for s in catalog.eligible(region, child_age))
ItemBound = create_model("CasePlanItemBound", __base__=CasePlanItem,
                         service_id=(Literal[ids], ...))
```

Декодер OpenAI физически не может вернуть значение вне этого списка.
Вторая линия защиты — `catalog.validate_plan_items`: отсеивает шаги,
не подходящие по возрасту или региону, и пишет причину в журнал куратора.

Аналогично ограничены `priority`, `responsible_role`, `status` и `blocker.type`.

### Эскалация

Механическая, без участия AI (`backend/app/deadline.py`):

```
status != DONE AND due_date < today  →  OVERDUE
1 день → родителю · 3 → родителю и куратору · 7 → эскалация · 14 → высокий уровень
```

Пересчёт происходит при каждом чтении плана, фоновые задачи не нужны.

## Справочник организаций

ПМПК, МСЭК и центры различаются по районам, а адреса и телефоны меняются,
поэтому они вынесены из кода в редактируемую базу. Куратор ведёт их на
странице «Справочник организаций» (значок булавки в панели куратора):
название, услуга, регион, район, адрес, телефон, контактное лицо, часы
приёма, портал и примечание.

Организация привязывается к услуге из каталога, поэтому попадает прямо
в шаг плана: родитель видит, куда идти и кому звонить, не выходя из плана.
Телефон на мобильном — кликабельный.

Организацию можно скрыть от родителей, не удаляя: флажок «показывается
родителям». Записи из статического справочника переносятся в базу при
первом запуске.

## Оговорки

Существенно для защиты — об этом лучше сказать самим:

- **Сроки услуг условные.** Проставлены правдоподобные значения, помечены
  в `services.json` (`deadlines_are_provisional: true`) и в интерфейсе.
  Куратор правит срок каждого шага вручную. Замена на нормативные — правка одного файла.
- **PHQ-9 вместо шкалы Бека.** BDI-II лицензируется правообладателем и не может
  использоваться в публичном продукте. PHQ-9 — открытая валидированная шкала.
  Это скрининг, а не диагноз.
- **Данные кейсов синтетические**, персональных данных в репозитории нет.
- **Родитель видит план сразу после интервью.** Пункт 9 исходного ТЗ предлагал
  показывать план только после подтверждения куратором. По решению заказчика
  схема изменена: ожидание проверки стоило бы семье времени, а именно его
  продукт и экономит. Куратор подключается параллельно — правит шаги, ведёт
  статусы и ставит отметку о проверке; правки видны родителю немедленно.
  До отметки план помечен в интерфейсе как предварительный.
- **Аутентификация упрощена**: PBKDF2 и токен в localStorage. Для реального
  внедрения требуются bcrypt или argon2, HttpOnly-cookie и HTTPS.
- **AI не ставит диагноз и не назначает лечение** — это зафиксировано
  и в системном промпте, и в ограничениях схемы.

## Проверки

Сквозной тест на живой модели (`/tmp/e2e.py` в истории разработки) проверяет:

| Проверка | Результат |
|---|---|
| Все `service_id` в плане есть в каталоге | пройдена |
| Интервью укладывается в 8–12 вопросов | пройдена |
| Один `question_id` не задаётся дважды | пройдена |
| У каждого шага есть объяснение для родителя | пройдена |
| Приоритеты только HIGH / MEDIUM / LOW | пройдена |
| Уже пройденные семьёй шаги в план не попадают | пройдена |

Вёрстка снята headless-браузером на 390px и 1440px: горизонтального
переполнения нет, зон нажатия мельче 40px нет, ошибок в консоли нет.

### Что нашли проверки и как исправлено

- **Модель повторяла `question_id`** — ответ перезаписывал предыдущий и состояние
  собиралось неверно. Теперь список заданных кодов уходит в промпт, а сервер
  дополнительно переименовывает повтор.
- **В план попадали уже пройденные шаги** — семье с оформленной инвалидностью
  предлагалось снова идти на МСЭ. Добавлен `ai.completed_services`: выводит
  пройденное из состояния кейса и отсеивает такие шаги, записывая причину
  в журнал куратора.
- **Интервью растягивалось до 14 вопросов** — верхняя граница теперь держится
  сервером, а не просьбой в промпте.
- **Регион спрашивался свободным текстом** — ответ «Караганды» не распознался бы,
  и подобрался бы неверный каталог. Регион и возраст теперь спрашивает система
  фиксированным списком, модель начинает с третьего вопроса.
- **Родителю показывался текст «Failed to fetch»** — заменено на человеческое
  объяснение; двойное монтирование в dev-режиме больше не создаёт лишний кейс.
