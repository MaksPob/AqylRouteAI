# AqylRoute AI

**Межведомственный маршрут семьи ребёнка с расстройством аутистического спектра.**
AI-интервью → Case Plan → контроль сроков → эскалация просрочки.

Прототип разработан для Карагандинского медицинского университета.

---

## Проблема

Родители детей с РАС теряются между тремя ведомствами — здравоохранением (МЗ),
соцзащитой (МТСЗН) и просвещением (МПР) — и повторно собирают одни и те же документы.
Специалисты при этом не видят полный маршрут ребёнка. Помощь приходит позже, чем могла бы.

**Что делает продукт.** За 12 вопросов определяет, где именно находится семья, и
превращает разрозненную информацию в один проверяемый план: с ответственными,
сроками, документами и видимой точкой, где маршрут остановился.

## Быстрый старт

```bash
cd ~/Desktop/AqylRouteAI
./start.sh
```

Скрипт сам создаст окружение, установит зависимости и откроет http://localhost:3000

### Запуск вручную

Нужны **две вкладки терминала** — фронтенд и бэкенд работают как отдельные процессы.

Вкладка 1, бэкенд (порт 8000):

```bash
cd ~/Desktop/AqylRouteAI/backend
.venv/bin/uvicorn app.main:app --port 8000 --reload
```

Вкладка 2, фронтенд (порт 3000):

```bash
cd ~/Desktop/AqylRouteAI/frontend
npm run dev
```

Открыть **http://localhost:3000**. Остановка — `Ctrl+C` в каждой вкладке.

### Если порт занят

```bash
pkill -f "next dev"; pkill -f uvicorn
```

Или занять другой порт: `npm run dev -- --port 3001`

### Развёртывание на другом компьютере

Поставить нужно только две вещи — остальное скрипт установит сам.

| Требуется | macOS | Windows и Linux |
|---|---|---|
| Python 3.11+ | `brew install python@3.12` | [python.org/downloads](https://www.python.org/downloads/) · `sudo apt install python3 python3-venv` |
| Node.js 20+ | `brew install node` | [nodejs.org](https://nodejs.org) · `sudo apt install nodejs npm` |

Дальше три команды:

```bash
git clone https://github.com/MaksPob/AqylRouteAI.git
cd AqylRouteAI
./start.sh
```

Первый запуск занимает 3–5 минут — ставятся зависимости. Браузер откроется сам.

Скрипт проверит версии Python и Node, установит зависимости, создаст `.env`
из шаблона, предложит освободить занятые порты и дождётся готовности сервисов.
Ключ OpenAI не обязателен: без него работает демонстрационный режим.

### Установка с нуля

Если папки `backend/.venv` или `frontend/node_modules` нет:

```bash
cd ~/Desktop/AqylRouteAI

python3 -m venv backend/.venv
backend/.venv/bin/pip install fastapi uvicorn[standard] openai pydantic python-multipart

cd frontend && npm install
```

Требуется **Python 3.11+** и **Node.js 20+**.

## Ключ OpenAI

Приложение **работает и без ключа** — в демонстрационном режиме планировщик
детерминированный, по тому же справочнику услуг. Режим виден внизу страницы входа.

Чтобы включить живую модель, скопировать `.env.example` в `.env` и вписать ключ:

```ini
OPENAI_API_KEY=sk-proj-...
OPENAI_MODEL=gpt-4o-mini
INTERVIEW_MODE=adaptive
CURATOR_INVITE_CODE=KMU-2026
```

Один прогон интервью с построением плана — примерно **$0.01–0.02**.

`INTERVIEW_MODE` задаёт, как звучат вопросы:

- `adaptive` — AI переформулирует их под контекст семьи: «Вы говорили, что у вас
  есть справка об инвалидности — оформлена ли она официально?»
- `canonical` — вопросы звучат строго как в справочнике.

После правки `.env` бэкенд нужно перезапустить.

## Как это работает

```
РОДИТЕЛЬ
   │
   ↓  12 вопросов, адаптивный порядок
AI-ИНТЕРВЬЮ
   │
   ↓  извлечение структуры
CASE STATE — документы, услуги, проблемы, состояние родителя
   │
   ↓  ограничение выбора
SERVICE CATALOG — 20 услуг, 5 этапов, 3 региона
   │
   ↓  structured outputs
AI CASE PLAN — шаги с приоритетом, сроком, ответственным, объяснением
   │
   ├──────────────────────────┐
   ↓                          ↓
РОДИТЕЛЬ видит план       КУРАТОР правит сроки и шаги,
сразу, помечен как        ведёт статусы, снимает блокеры,
предварительный           ставит отметку о проверке
   │                          │
   └──────────┬───────────────┘   правки видны родителю немедленно
              ↓
   СТАТУСЫ → DEADLINE ENGINE → OVERDUE → ЭСКАЛАЦИЯ 1/3/7/14 дней
```

### Почему AI не может выдумать действие

Требование ТЗ «AI берёт действия только из справочника услуг» выполняется
**типом, а не просьбой в промпте**. Перед вызовом модели список допустимых
`service_id` подставляется в JSON Schema как `Literal`, суженный до услуг,
доступных этому региону и возрасту:

```python
ids = tuple(s["id"] for s in catalog.eligible(region, child_age))
ItemBound = create_model("CasePlanItemBound", __base__=CasePlanItem,
                         service_id=(Literal[ids], ...))
```

Декодер OpenAI физически не может вернуть значение вне этого списка. Так же
ограничены `priority`, `responsible_role`, `status`, `blocker.type` и
`next_question_id` в интервью.

### Что делает AI, а что код

| Делает модель | Делает код, без участия AI |
|---|---|
| Выбирает и формулирует следующий вопрос | Просрочка: срок прошёл и статус не DONE |
| Извлекает состояние кейса из ответов | Эскалация по порогам 1, 3, 7, 14 дней |
| Подбирает шаги, приоритеты, сроки | Порядок процедур: МСЭ невозможна без формы №031/у |
| Пишет объяснение для родителя | Этап маршрута — из документов семьи |
| | Что семья уже прошла — из ответов |

Формулировка для защиты: **AI отвечает за понимание и объяснение, код — за
процедуру и сроки.**

### Три линии защиты плана

1. **Схема** — `service_id` только из каталога региона и возраста.
2. **`catalog.validate_plan_items`** — отсев услуг, не подходящих возрасту или региону.
3. **`ai.drop_completed` и `ai.enforce_prerequisites`** — убирают уже пройденное
   и достраивают недостающие предпосылки. Если модель выдала МСЭ без формы
   №031/у, шаг ВКК добавляется автоматически, а зависимости пересчитываются.

Услуги, о которых интервью не дало данных, в план **не попадают**, а выводятся
куратору отдельным блоком «Нужно уточнить у родителя». Это честнее, чем ставить
шаг наугад.

## Возможности

### Родитель

- Адаптивное интервью: 12 вопросов ТЗ, вопросы с известным ответом пропускаются
- План человеческим языком: что сделать, до какого числа, какие документы, куда идти
- Фокус на трёх ближайших шагах, остальное по кнопке
- Контакты организаций прямо в шаге: адрес, телефон (кликабельный), часы приёма
- Ведение статусов: «выполнено», «начал заниматься», «жду ответа»
- Загрузка документов: PDF и фотографии до 10 МБ, drag-and-drop
- Скрининг собственного состояния PHQ-9 с отслеживанием динамики

### Куратор

- Сводка по всем кейсам: просрочено, заблокировано, не проверено
- Аналитика по причинам остановки, а не просто «17 просрочено»
- Правка шагов: название, приоритет, ответственный, срок — видна родителю сразу
- Блокеры с типом и описанием
- Подтверждение статусов, отмеченных родителем
- Справочник организаций: ПМПК, МСЭК и центры по районам
- История кейса и уведомления об эскалации

---

## Справочник организаций

ПМПК и МСЭК свои в каждом районе, адреса и телефоны меняются — поэтому они
вынесены из кода в редактируемую базу. Куратор ведёт их сам: значок булавки
в панели куратора.

Поля: название, услуга из каталога, регион, район, адрес, телефон, контактное
лицо, электронная почта, портал, часы приёма, примечание.

Организация привязана к услуге, поэтому попадает прямо в шаг плана. Её можно
скрыть от родителей, не удаляя, — флажок «показывается родителям».

## Синтетические кейсы

### CASE-000001 «Раннее начало» — вход `parent`

Алихан, 3 года, Астана. Диагноз не подтверждён, документов нет, родитель в фазе
шока. AI строит маршрут с нуля: консультация психиатра → ВКК и форма №031/у →
МСЭ → ИПАР → пособия. Каждый шаг ссылается на предыдущий. План уже открыт семье,
куратор ещё не проверял.

**Показывает:** построение маршрута с нуля и соблюдение порядка процедур.

### CASE-000002 «Застрявший маршрут» — вход `parent2`

Амина, 6 лет, Карагандинская область. Диагноз, инвалидность и ИПАР оформлены —
формально всё в порядке. Но ПМПК просрочена на 12 дней перед первым классом,
а услуга из ИПАР не предоставляется третий месяц. Родитель в фазе депрессии.

**Показывает:** просрочку, эскалацию, блокер «ждём организацию» и поддержку
родителя. Это главный кейс: он демонстрирует ценность продукта.

Оба кейса **детерминированы** — воспроизводятся одинаково при каждом запуске,
поэтому репетиция совпадёт с показом.

Подробное описание со сценарием демонстрации — в файле `AqylRoute-КЕЙСЫ.docx`.

## Проверки

Сквозной тест на живой модели проверяет:

| Проверка | Результат |
|---|---|
| Все `service_id` в плане есть в каталоге | пройдена |
| Интервью укладывается в 8–12 вопросов | пройдена |
| Один `question_id` не задаётся дважды | пройдена |
| У каждого шага есть объяснение для родителя | пройдена |
| Приоритеты только HIGH, MEDIUM, LOW | пройдена |
| Уже пройденные семьёй шаги в план не попадают | пройдена |
| Услуги без данных из интервью в план не попадают | пройдена |
| Порядок процедур соблюдён | пройдена |

Вёрстка снята headless-браузером на 390px и 1440px: горизонтального переполнения
нет, зон нажатия мельче 40px нет, ошибок в консоли нет.

Проверки прав доступа: чужой родитель не может скачать документ (403), исполняемые
файлы не принимаются, роль куратора без кода не выдаётся (403), родитель не может
добавить организацию (403).

## Известные ограничения

Существенно для защиты — об этом лучше сказать самим.

- **Сроки услуг условные.** Проставлены правдоподобные значения, помечены
  в `services.json` полем `deadlines_are_provisional` и в интерфейсе. Куратор
  правит срок каждого шага вручную. Замена на нормативные — правка одного файла.
- **PHQ-9 вместо шкалы Бека.** BDI-II лицензируется правообладателем и не может
  использоваться в публичном продукте. PHQ-9 — открытая валидированная шкала,
  применяется в первичном звене во всём мире. Это скрининг, а не диагноз.
- **Родитель видит план сразу.** Пункт 9 исходного ТЗ предлагал показывать план
  только после подтверждения куратором. По решению заказчика схема изменена:
  ожидание проверки стоило бы семье времени, а именно его продукт и экономит.
  Куратор работает параллельно, правки видны немедленно, до отметки о проверке
  план помечен как предварительный. Риск ограничен тем, что AI не может выйти
  за справочник услуг и не соблюсти порядок процедур.
- **Данные кейсов синтетические**, персональных данных в репозитории нет.
- **Аутентификация упрощена:** PBKDF2 и токен в localStorage. Для реального
  внедрения нужны bcrypt или argon2, HttpOnly-cookie и HTTPS.
- **AI не ставит диагноз и не назначает лечение** — закреплено в системном
  промпте и в ограничениях схемы.
- **SQLite вместо Supabase.** Оба варианта разрешены требованием. SQLite выбран
  ради скорости развёртывания; переход на Supabase затрагивает только `db.py`.

## Решение проблем

**Порт занят**

```bash
pkill -f "next dev"; pkill -f uvicorn
```

**Бэкенд не стартует.** Проверить, что окружение создано: `ls backend/.venv/bin/uvicorn`
Если файла нет — см. раздел «Установка с нуля».

**Интерфейс говорит «Сервер недоступен».** Бэкенд не запущен или занят другой порт.
Проверить: `curl http://127.0.0.1:8000/api/health`

**AI в демонстрационном режиме при наличии ключа.** Файл `.env` должен лежать
в корне проекта, а не в `backend/`. Бэкенд нужно перезапустить после правки.

**Ошибка `insufficient_quota`.** Закончились кредиты OpenAI:
https://platform.openai.com/settings/organization/billing
Приложение продолжит работать в демонстрационном режиме.

**Начать с чистой базы**

```bash
rm backend/aqylroute.db && rm -rf backend/uploads
```

Синтетические кейсы и справочник организаций пересоздадутся при следующем запуске.
